# 2D 静态资源风格统一与全流程方案

> 状态：方案文档，待需求确认后进入开发  
> 适用：Godot 4.6 / 固定 135° 偏航、45° 俯角 / shader 地形 / AI 生成 2D 立牌  
> 目标：让 AI 生成的 2D 静态资源看起来属于同一个世界，而不是“贴上去的素材”  
> 本文档只描述流程、规格、验收和分工；确认需求后再实施。

---

## 0. 一句话结论

**引擎负责几何、相机、光照；AI 负责表面材质与细节；2D 后处理负责把两者粘在一起。**

不是继续“抽卡”，而是：

```
Art Bible → 参考板 → Blockout → AI 生成 → 2D 归一化 → 引擎内粘合 → 真实场景验收
```

独木桥的问题不是“桥画得不好”，而是它把错误的相机、光照、色阶、细节密度和阴影一起烤进了 PNG。单靠调位置、调 `art_size` 解决不了。

---

## 1. 问题定义

### 1.1 当前现象

- 地形由 shader 实时生成：柔和的色块、噪声、坡度光照、雪线、岩石、雾。
- 静态资源是 AI 生成的 2D 立牌：图片里已经带有了自己的相机、方向光、阴影、色盘和细节。
- 两者放在一起时，资产看起来“完全不是一个画风”，即使位置、占地和锚点都正确。

### 1.2 六个不匹配

| 不匹配 | 具体表现 | 根因 |
|---|---|---|
| 相机/透视 | 资产像从另一个角度看 | AI 生成了自己的 2:1/3/4 视角 |
| 光照方向 | 资产亮面和地形亮面不一致 | 图片里烘焙了另一套太阳方向 |
| 色盘/对比 | 资产过饱和、过暗或过亮 | AI 图不在 terrain 色盘内 |
| 细节频率 | 资产比地形“太锐、太密” | AI 纹理细节高于 shader 噪声 |
| 边缘处理 | 资产有明显硬边/描边/透明边缘 | 与地形的柔和过渡不一致 |
| 接地感 | 资产像浮在地面上 | 没有接触阴影、AO、地形色贴片 |

### 1.3 为什么独木桥特别明显

- 桥是“跨过地形”的资产，透视、长度、接触点都被放大；
- 一张固定 PNG 无法适配不同河宽；
- 桥下没有接触阴影，水面和桥之间缺少压暗；
- AI 图里的木料高光/暗部方向与地形 shader 不一致；
- 桥的支撑脚没有“压”在两岸，视觉上就会漂浮。

结论：独木桥不是单点参数问题，而是“资产生成方式和引擎渲染方式不在同一个世界”。

## 2. 设计原则

1. **一个世界**：所有资产共享同一相机、光照方向、色盘、尺度、细节密度、阴影规则。
2. **职责分离**：引擎决定几何/相机/光照；AI 只提供材质、纹理、风格化细节。
3. **参考优先**：3D blockout 只作为 AI 的构图参考，不是最终资产。
4. **先结构后风格**：透视、占地、锚点、跨度正确之后，再谈颜色和笔触。
5. **生成后归一化**：任何 AI 图都必须经过尺寸、色盘、对比、细节、阴影清理。
6. **引擎内验收**：只在图片浏览器里看不算完成，必须放进真实河道/光照/相机里截图。
7. **可变跨度优先模块化**：桥、栅栏、围墙不要依赖一张固定图硬拉。

## 3. 全流程

### 阶段 0：建立 Art Bible

在生成任何资产前，先固定以下规则。建议单独建 `ArtBible.md`。

| 项目 | 要求 | 示例 |
|---|---|---|
| 相机 | 固定 45°、正交/透视、yaw/pitch | yaw 135°、pitch 45°、正交 |
| 像素密度 | 每格多少像素、最终屏幕分辨率 | 1 格 = 32 px（可调整） |
| 光照 | 方位角、高度角、软硬、阴影颜色 | 方位 150°、高度 35°、阴影偏冷 |
| 色盘 | 8–32 个主色 hex | 草地、沙、岩石、木、屋顶、水 |
| 描边 | 有无描边、宽度、颜色 | 无粗描边，边缘 1px 暗色 |
| 细节 | 纹理频率上限 | 不超过地形噪声的 1.5 倍 |
| 材质 | 木/石/瓦/布/金属的规则 | 木纹方向、瓦片密度、金属反光 |
| 阴影 | 接触阴影颜色/软度/偏移 | 地形暗色、半径 0.3 格、向下偏 |
| 锚点 | 脚底/中心/端口 | 桥=桥面中心；建筑=占地中心 |

**交付物：**
- 一页 Art Bible（可直接给 AI 作为提示词前缀）；
- 6–12 张参考图组成的 reference board；
- 明确“像/不像”的标注。

参考：
- Seele AI 的一致性清单与 6 步流程：  
  https://www.seeles.ai/resources/blogs/consistent-ai-game-assets-workflow
- Layer AI 的等距资产训练规则：  
  https://help.layer.ai/en/articles/12055377-how-to-forge-consistent-isometric-game-assets

### 阶段 1：资产清单与规格

为第一批资产建立清单。不要一次做全部，先选 3–5 个代表资产。

| 字段 | 说明 |
|---|---|
| 资产 id / 名称 | 稳定 id，例如 `bridge_log_01` |
| 类型 | 建筑 / 桥 / 栅栏 / 树 / 装饰 |
| 优先级 | Hero（最显眼）/ 普通 / 背景 |
| 占地 | 格数、形状；桥要写跨度范围 |
| 锚点 | 脚底中心 / 端口 / 桥面中心 |
| 方向 | 需要几个方向变体（4 向/8 向/镜像） |
| 模块化 | 桥段、栅栏段、墙段是否可拼接 |
| 目标尺寸 | 格数 × 像素密度 |
| 参考图 | 该资产对应的 reference |
| 验收场景 | 放在哪张地图、哪个位置、哪个相机 |

**第一版建议先做：**
1. 独木桥（Hero，跨度 2–4 格）；
2. 一个建筑（Hero，2×2 或 3×3）；
3. 一段栅栏（模块化）；
4. 一棵树（普通）；
5. 一块石头/装饰（验证接触阴影和色盘）。

### 阶段 2：参考板与 Blockout

#### 2.1 参考板

- 从现有地形截图里裁 6–12 张：草地、沙、岩石、水、道路、雪、阴影；
- 加 3–5 张你认可的资产（哪怕来自其他游戏），标注“只要这个感觉”；
- 不要混入像素画、写实照片、不同光照方向的图；
- 参考板是 IP-Adapter 的 style reference，也是人工复盘的依据。

#### 2.2 Blockout

目的：把**相机、透视、比例、轮廓、光向**从 AI 手里拿回来。

- 在 Godot 或 Blender 里用简单几何搭出资产：
  - 桥：圆柱/方块 + 桥墩；
  - 建筑：盒子 + 屋顶；
  - 树：球 + 柱；
- 相机必须与游戏一致（yaw 135°、pitch 45°，正交优先）；
- 光照必须与 `light_azimuth/light_elevation` 一致；
- 渲染以下参考图：
  - 色块/材质 id 图；
  - 深度图；
  - 线稿/边缘图；
  - AO/接触阴影图（可选）。

**3D 只作为参考，不进入最终 2D 资产。**

如果不想做 3D blockout，最低限度也要在 Godot 里用 2D 多边形按 45° 投影画一个色块轮廓，作为 ControlNet 的 structure 输入。

参考：
- SAE 的 3D blockout + AI 工作流：  
  https://creo.sae.edu.au/staffscholarship/250/

### 阶段 3：AI 生成

#### 3.1 工具分工

| 工具 | 作用 |
|---|---|
| ControlNet（Depth / Canny / LineArt / MLSD） | 锁结构、轮廓、透视 |
| IP-Adapter | 用参考图锁风格、色盘、材质 |
| LoRA | 长期锁死一套画风（15–30 张一致资产） |
| 固定 seed | 保证批次可复现 |
| 批量生成 | 每个资产 8–16 张候选，不要只抽一张 |

参考：
- Playgama 的 ControlNet/IP-Adapter/LoRA 分工：  
  https://playgama.com/blog/business-faqs/how-to-use-controlnet-ip-adapter-or-loras-for-consistent-gam/
- ComfyUI IPAdapter Plus：  
  https://github.com/cubiq/ComfyUI_IPAdapter_plus
- ControlNet：  
  https://github.com/lllyasviel/ControlNet

#### 3.2 提示词模板

固定前缀/后缀，只替换资产描述：

```
[视角] 45-degree top-down isometric game asset, orthographic, fixed camera,
[对象] a wooden single-log bridge with two stone supports,
[风格] painterly stylized strategy-game terrain, soft diffuse light from top-left,
low contrast, limited warm earth palette, no hard black outline,
[技术要求] transparent background, centered, no ground shadow, no text, no UI,
[负面] photorealistic, high contrast, hard outline, different perspective, cast shadow
```

注意：
- **不要**让 AI 自己画地面阴影（容易和引擎光照冲突）；
- 不要混用不同光照方向的参考图；
- 不要只生成单个资产，最好按同批次生成全套（桥/建筑/栅栏）。

#### 3.3 候选筛选

按 1–5 分打分，任何一项低于 4 就淘汰：

- 透视/相机；
- 比例/占地；
- 色盘；
- 轮廓可读性；
- 与参考板的相似度。

### 阶段 4：2D 归一化

每张入选图都要经过：

1. **裁剪**：去掉多余透明边，保留统一 safety margin；
2. **尺寸**：按目标格数缩放，保持像素密度一致；
3. **锚点**：按脚底/桥面中心重新对齐；
4. **色盘**：用 LAB 直方图匹配或 nearest-palette 对齐地形参考；
5. **对比/细节**：降低过强对比，减少过密高频细节；
6. **阴影**：去掉 AI 画的落地阴影，交给引擎；
7. **边缘**：必要时加 1px 暗边/柔化边缘，避免硬切；
8. **命名**：`category_asset_variant_direction.png`。

颜色匹配工具：
- `color-matcher`（Reinhard / 直方图 / MKL）：  
  https://github.com/hahnec/color-matcher
- scikit-image `match_histograms`：  
  https://scikit-image.org/docs/stable/auto_examples/transform/plot_histogram_matching.html

建议：**只匹配亮度**，保留原图色相，避免木头被染成地形绿。

### 阶段 5：引擎内粘合

这是 2D 资源最关键的一步。单独一张“完美”的图，放进引擎仍然可能突兀；需要：

1. **立牌 shader**
   - 共享地形噪声/颗粒；
   - 按世界位置加环境雾/距离 tint；
   - 色盘/亮度微调；
   - 可选：用 normal map 做方向光（固定相机/固定太阳时可直接烘焙，不必做）。

2. **接触阴影**
   - 每个建筑/桥/树底部加软阴影贴片；
   - 阴影颜色取地形暗部，不要纯黑；
   - 桥下水面的暗部要单独处理。

3. **地形色贴片 / 树根草垫**
   - 在资产底部加少量草/石/泥的过渡贴片，遮住 PNG 硬边；
   - 树类物件不走贴片：`MapRuntime.set_ground_props` 按脚底生成 `u_prop_ground` 遮罩，地表先长一圈同色草；立牌着色器再把贴图草垫的草色像素淡到约 15%，由地形草接管边缘；
   - 桥端加河岸贴片，让桥“插进”地面。

4. **全屏后处理**
   - CanvasLayer 全屏 shader 做轻微 LUT、对比、雾、颗粒；
   - 让地形和立牌共享同一套最终色阶。

参考：
- Godot 3D LUT 文档：  
  https://docs.godotengine.org/en/stable/tutorials/3d/environment_and_post_processing.html
- Calinou 3D LUT demo：  
  https://github.com/Calinou/godot-3d-lut-demo
- VesperaFX（调色板映射/后处理）：  
  https://github.com/devkcud/vesperafx
- Palettizer：  
  https://godotengine.org/asset-library/asset/5064
- 2D 阴影 shader：  
  https://github.com/TABmk/godot-2d-shadow-shader

**注意：**
- Godot 的 Environment 3D LUT 主要作用于 3D 渲染；2D CanvasItem 管线需要全屏 CanvasLayer 后处理或立牌 shader。
- 调色板后处理对 alpha 混合材质可能不生效；立牌优先用 alpha scissor/dither，或单独处理。

### 阶段 6：验收

每个资产必须在真实场景里验收：

- 固定相机、固定 ppm 截图；
- 和地形参考图放在一起；
- 检查透视、光向、色盘、尺度、接触阴影、边缘、细节；
- 记录“通过/不通过”的原因，不通过就回到阶段 3/4。

建议建立：
- `AssetLab` 固定测试场景；
- 每个资产的 golden screenshot；
- 一份验收表（透视、比例、色盘、光照、接地、可读性）。

### 阶段 7：变体与模块化

- **方向**：固定相机下，4 向优先；需要 8 向时先生成 turnaround sheet 再拆；
- **桥**：两端桥墩 + 可重复桥板段，按跨度拼 2/3/4 段；
- **栅栏/墙**：直/角/T/端模块 + 端口；
- **LOD**：远景可用低细节版本，避免细节密度不一致；
- **图集**：同批资产打包 atlas，减少 draw call。

### 阶段 8：资产入库

- 统一目录：`Assets/.../Processed/<category>/`；
- 统一命名：`<category>_<asset>_<variant>_<dir>.png`；
- 每个资产一份 metadata：尺寸、锚点、占地、方向、跨度、色盘匹配参考；
- 资产定义与图像分开版本管理；
- 替换旧资产时保留旧版本，避免不可逆。

## 4. 2D 专用技术清单

| 技术 | 作用 | 备注 |
|---|---|---|
| 2D blockout | 给 AI 正确透视/轮廓 | 3D 白模或 2D 色块均可 |
| ControlNet | 锁结构 | Depth/Canny/LineArt |
| IP-Adapter | 锁风格/色盘 | 参考板 6–12 张 |
| LoRA | 长期锁画风 | 15–30 张一致资产 |
| LAB 颜色迁移 | 把 AI 图拉回地形色盘 | 只匹配亮度更稳 |
| 2D 接触阴影 | 解决“浮空/贴上去” | 软阴影贴片或 shader |
| 立牌 shader | 共享噪声/雾/颗粒/tint | 2D 管线的核心粘合层 |
| 全屏后处理 | 统一最终色阶 | CanvasLayer，不是 3D Environment |
| Normal map（可选） | 动态光照 | 固定太阳时可不用 |
| 模块化桥段 | 适配不同河宽 | 优于一张图硬拉 |
| 方向变体 | 固定相机下 4/8 向 | 先做 turnaround sheet |

## 5. 独木桥案例

### 5.1 当前情况

- 实例：`(29, 32)`，方向 0，占地 1×2；
- 两格都是浅水；
- 河面在该段约 4 格宽；
- 桥图约 1.8 格宽，明显短于河面；
- 桥下没有接触阴影，视觉上像漂浮的木头；
- 桥是 `NONE` 阻挡，A* 可走，但桥本身不改变水面代价。

### 5.2 目标规格

- 跨度：2–4 格可配；
- 两端桥墩/支撑；
- 桥面高度由两岸高度决定；
- 4 个方向（至少 2 个主方向）；
- 桥面通行代价接近道路；
- 接触阴影 + 河岸贴片。

### 5.3 三个方案

| 方案 | 做法 | 成本 | 效果 |
|---|---|---|---|
| A. 修现有图 | 调色、加阴影、缩放 | 低 | 只能缓解，透视仍不对 |
| B. Blockout → AI 重生成 | 45° 白模 + ControlNet/IP-Adapter | 中 | 透视/光照正确，推荐 |
| C. 模块化/程序化桥 | 桥墩 + 桥板段，AI 只出木纹 | 高 | 最稳，适配不同河宽 |

**推荐：B 作为第一版，C 作为长期方案。**

## 7. 需要你提供的需求

请按这一节给我一份“需求包”。收到后我先做 M1（Art Bible + 参考板 + 规格表），确认后再进入开发。

### 7.1 必填

1. **视觉目标**
   - 6–12 张“像这个”的参考图：现有地形截图、其他游戏截图、手绘都可以；
   - 标注哪些地方像、哪些不像（用文字或圈图）；
   - 特别注明：你希望资产“融进地形”还是“稍微跳出来但可读”。

2. **相机与尺度**
   - 当前游戏相机参数（yaw、pitch、正交/透视、ppm、height_scale）；
   - 目标分辨率、每格像素密度；
   - 资产希望占多少格。

3. **光照与色盘**
   - `light_azimuth`、`light_elevation`、阴影软硬；
   - 地形色盘 hex（草地、沙、岩石、木、屋顶、水、雪）；
   - 阴影色（不要纯黑，给一个偏冷或偏暖的 hex）。

4. **第一批资产清单**
   - 资产名称/id；
   - 类型（建筑/桥/栅栏/树/装饰）；
   - Hero / 普通 / 背景；

## 9. 风险与取舍

- **2D 资产不能像 3D 一样实时重打光**：固定相机/太阳时直接烘焙；需要变化时再上 normal map。
- **一张图适配所有跨度不现实**：桥/栅栏必须模块化或做长度变体。
- **AI 一致性不是 100%**：需要参考板、筛选、归一化和人工验收。
- **后处理不是万能**：错误的透视/光照无法靠调色拯救。
- **调色板后处理对 alpha 混合有限制**：立牌要用 alpha scissor/dither 或单独处理。
- **资产授权**：确认模型/LoRA 的商用许可；不要把受限素材直接进最终包。
- **最终审美仍是人的工作**：AI 可以生成候选、做归一化，但不能替你判断“像不像这个世界”。

---

## 10. 结论

2D 资源完全可以按这套思路做，但要记住：

1. **3D blockout 只是参考，不是最终资产；**
2. **引擎负责几何/相机/光照，AI 负责材质/细节；**
3. **2D 的粘合靠立牌 shader、接触阴影、共享噪声/雾/后处理；**
4. **桥这类可变跨度资产，模块化比一张 AI 图更可靠；**
5. **所有资产必须在真实场景里验收。**

之前桥借用了 `StaticAssetDef`/`PropsData`：占地、阻挡、surface_cost 都能复用，但桥的实际跨度是启动时扫河岸得到的，和固定 def 占地不一致；桥的专有数据（跨度、桥面高度、栏杆/桥墩）也没有实例化。编辑器里它出现在“资源库”而不是道路工具，属于“用静态物件管线承载的静态结构”。

现在桥完全独立：

- **数据**：`GridData/bridges_data.gd`，保存 `kinds / starts / ends`；`starts/ends` 是两个 **1×1 桥座**（必须落在陆地），两座之间的格子是**桥身**（必须全是水，至少 1 格，长度不限）。
- **边车**：与地图同名的 `.bridges.tres`（例如 `level_1_content.bridges.tres`）。
- **编辑器**：道路面板下新增“桥（拖动跨河，直线）”：独木桥/木桥/石桥三个按钮；左键拖动一条直线，右键删除；预览只画直线，斜拖自动吸附到主导轴，**不会拐弯**。
- **校验**：越界、斜线、桥座在水里、桥身含陆地/没有水、穿山、压静态物件、与已有桥重叠，全部拒绝；预览用高亮格区分两个桥座，中间桥身用桥色，非法显示红色。
- **渲染**：`example/procedural_bridge.gd` 按“类型 + 两个桥座”生成，不再 auto-scan、不再读取 `StaticAssetDef`；两个桥座在陆地各占 1 格，桥身在水上；木/石/独木的桥面、栏杆/护栏、桥座/踏步、木桩都保留；桥下地面/水面投影已按反馈删除。
- **通行**：`MapRuntime.apply_bridges()` 把桥线格子写成 `surface_cost = 0.6`；`surface_z()` 返回桥面高度；demo 角色能走上桥面。
- **撤销/保存**：桥数据进入整图快照；地图保存时写 `.bridges.tres`；地图缩小会丢弃越界桥。
- **迁移**：`level_1_content` 的旧静态桥 prop 已移除，换成桥层木桥 `(29,35)→(32,35)`；旧的 `cv_bridge_*` 静态定义、`narrow_wooden_bridge` 静态定义及其 catalog 条目已删除，之前的 4×1 / 1×4 测试图也已删除。`level_1` 当前没有使用静态桥。

验证结果：桥线 A* 路径长度 4；桥格 `surface_z = 4.70`；demo 角色立在桥面（[游戏-桥面](../截图/游戏-桥面.png)）；撤销/重做、保存重开、右键删除均通过。

仍未解决：桥宽固定 1 格；不支持分叉/拐弯（由“拖动直线”的规则刻意限制）；石桥在很短的水面上墩距比例还可以继续调；矢量平涂与像素资产的媒介差异。

### 12.14 静态资源三点地基锚定（2026-11-03）

导入页新增可选的三点锚定，替代“只能做单侧垂直剪切、拖动时另一侧跟着跑”的旧对齐方式：

- 在图片地基上放 **左 / 前 / 右** 三个锚点，自动对应到占地（旋转后）的左 / 前 / 右三个角；第 4 个角由 2D 仿射自动推出。矩形占地投影后是平行四边形，三个非共线点正好确定仿射。
- 数据：`StaticAssetDef.anchors_src`（整张 PNG 像素，空 = 旧模式）+ `anchor_height`（地基线以上高度拉伸，0.25–3.0）；运行时 `GridProjection.anchor_affine()` 求 AABB / warp / 地基折线，`actor_card.setup_sprite_anchored()` + `actor_sprite.gdshader` 的 `u_use_warp / u_anchor_height` 分支采样。
- 导入页：锚点模式显示原图 + 三个手柄 + 到目标角的虚线 + 仿射/高度拉伸轮廓；「显示结果」查看贴合。拖动期间冻结取景，松手再适配，解决旧手柄“拖一侧另一侧动”的问题。
- 高度拉伸：`anchor_height` 以三锚点按 x 排序后的地基折线为基准，锚点不动、只拉伸/压缩折线以上部分；位置锚定和高度调整因此可以同时使用，不再互斥。地基是 V 形时上边缘会随坡线变化；要严格水平上边缘需四点模式。
- 限制：整张立牌仿射变形（竖线可能轻微倾斜），不是四点透视；直栅栏/平板底边三点共线，继续用旧 `art_lift`。旧 39 个定义不启用时外观完全不变。
