# 资产加工方案（canonical → 可用 sprite）

> 状态：**已执行第一批（2026-10-28）。** 85 个 raw → 110 个 RGBA PNG；逐族处置与 QA 见 [资产加工决策.md](资产加工决策.md)。  
> 适用范围：生成 Agent 只交 canonical 基准件和真实 raw；加工侧（我们）负责抠图、alpha、裁切、镜像扩展、限色、QA，最终交付 RGBA PNG。  
> **GridAtlas 本身不负责抠图/背景移除**；它只接收透明 PNG。

## 0. 分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| 生成 Agent | canonical 基准件、真实 raw 后缀、metadata/账本 | 角度矩阵、alpha、抠图、限色、裁切 |
| 加工侧（我们） | 抠图/alpha、裁切、baseline/pivot、H 镜像/组合、限色、阴影、QA、交付 | 重新设计建筑/重画结构 |
| GridAtlas | 导入 RGBA PNG、占地范围/放置/渲染 | 抠图、图片加工 |

## 2. 变换规则

| 变换 | 可用 | 不可用 / 注意 |
|---|---|---|
| **H 镜像（水平轴对称）** | 45° 直立建筑、围栏、墙、门、树、石头、对称道具 | 会翻转左右立面和两条地面轴；也会翻转烘焙光向。必须有平光/无侧影版本，否则左光变右光。 |
| **180° 点对称（旋转 180°）** | 俯视图标、贴花、平面纹样、完全对称的顶视件、minimap 图标 | **不要用于 45° 直立建筑/围栏**：会把上下颠倒，柱子/屋顶倒置。 |
| **V 镜像（垂直轴对称）** | 俯视平面件、对称纹样 | 直立物体不要用；等于上下翻转。 |
| **90° 旋转** | 仅适用于真正的俯视/平面贴图 | 45° 直立立牌不要用：立柱会倾斜、地面轴不再对齐。 |
| **组合/复制** | 长围栏、墙、桥、回廊 | 只复制 straight；不拉伸 corner/end；用同一 baseline 拼接。 |

**核心结论：45° 直立资产以 H 镜像为主；180° 点对称留给俯视/平面/对称件。**

> **不要混淆：** 2D 点对称（图片旋转 180°）会把直立物体上下颠倒；3D 绕竖轴 180° 的“背面视图”也不是 2D 变换，不能从一张 45° 立牌生成——那需要单独的背面 canonical，或真正的 3D 源。

## 3. 加工流程

### 3.1 输入与验证

- 读取 raw/：真实 `.jpg` 或 `.png`；记录 `actual_format`。
- 检查尺寸、内容 bbox、baseline、pivot、是否有文字/额外建筑/地面平台。
- 不覆盖 raw；所有输出写入 `delivery/`。

### 3.2 抠图 / alpha

- 本批（品红底像素画）**默认用品红键控**：`min(R,B)-G` 分级 → 全透明/软边/保留，再按 `min(R,B)-G` 去紫。键控能一次清掉背景、柱脚紫影和镂空缝隙；实测 110 个交付文件无软边、无品红残留。
- 本地 AI 抠图 skill（`remove-bg-ai.js`，免费、本地 ONNX）保留给非品红底素材；**不要用于镂空篱笆/栅栏**：AI 会把缝隙里的品红留成色块（见 `Processed/_pilot/E03_ai.png`）。
- 像素画后处理：
  - alpha 硬化（0/1），去掉软边；
  - 去品红/彩色 fringe；
  - 决定丢弃 AI 图里的烘焙阴影，统一补中性软阴影；
  - 检查细结构（栏杆、绳结、柱脚）不断线。
- 输出 RGBA PNG；记录 `has_alpha: true`。

### 3.3 裁切 / baseline / pivot

- 从 alpha 计算 content bbox；裁掉透明空白，保留 5–10% 边距。
- 统一 baseline：脚底/墙脚/桥面落在同一 y。
- 统一 pivot：默认 bottom-center；模块用端点/格角对齐。
- 按类型设定 art size / world height；建筑不要靠运行时 `scale` 调整。

> 注意：GridAtlas 的 `StaticAssetDef` 不存 pivot；立牌脚底固定为占地范围中心 + `art_offset`。
> baseline/pivot 只用于加工侧对齐与内容区处理，不会进入运行时锚点。

### 3.4 镜像/组合扩展

- 每个 canonical 生成：
  - `__base`；
  - `__mirror_h`（H 镜像）；
  - 需要时 `__rotate_180`（仅俯视/平面）；
  - 组合：`straight + straight + ...`、`corner + straight`、`bridge + ramp`。
- 镜像后检查光向、阴影、文字/图案是否翻转；不对称细节（门环、招牌）要决定是否接受。
- 长段拼接后做 tiling strip 测试；有缝/高度跳变就退回或标记 loose。

### 3.5 限色 / 清理

- 压到 12–24 色，去掉 JPEG 噪点/渐变/抖动。
- 清掉可读文字/书法；招牌/布幡保持空白。
- 统一描边粗细；清理品红边、半透明脏边。
- 中性阴影：参考 Tiny Swords 的 RGBA(22,28,46,69)，或单独阴影层；模块不要重复侧影。
- 输出下采样版本（约 192–220 px 内容高，视类型而定）。

### 3.6 命名与 metadata

- 基础：`CV-<CAT>-<NNN>_<slug>__base.png`
- 派生：`...__mirror_h.png`、`...__rotate_180.png`
- metadata 字段：
  - `canonical_id`
  - `design_variant`（v1/v2/材质）
  - `transform`（none/mirror_h/rotate_180/flip_v）
  - `content_bbox`
  - `baseline`
  - `pivot`
  - `art_size`
  - `has_alpha`
  - `palette_colors`
  - `source_raw`
  - `qa_status`
  - `tiling_check`
- 不要把同一设计的镜像件登记成新的设计变体。

### 3.7 QA

- [ ] 真 RGBA PNG；无品红边/白底/黑底。
- [ ] 内容 bbox 正确；baseline/pivot 一致。
- [ ] H 镜像后光向没有明显翻转；有翻转则退回平光版。
- [ ] 180° 只用于俯视/平面；直立件没有倒置。
- [ ] 模块 tiling strip 无缝、无高度跳变。
- [ ] 12–24 色、无 JPEG 噪点、无文字。
- [ ] 与同层 style 一致；不与 batch1/2 混风格。
- [ ] 生成 contact sheet；记录 review 路径。

## 4. E 模块专项

- **E01/E02/E03/E05**：每材质只接 4 个 canonical（straight/corner/end/gate）；加工侧 H 镜像生成另一轴/另一侧拐角，straight 复制长段。
- **E11**：4 个材质基准门；H 镜像另一侧；不做 H/V 两套。
- **E12**：straight/corner/end 三个 canonical；H 镜像 + 复制。
- **T03/T04**：基准桥 + 桥头/坡道；H 镜像另一方向；做桥面/道路高度连接测试。
- 若 canonical 本身有侧向阴影/方向光，先退回生成平光版；不要在加工侧硬修，否则镜像会重复阴影。
